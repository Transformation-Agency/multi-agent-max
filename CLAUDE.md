## Invariants

1. A ticket profile pass is LOCAL evidence only. Feature tickets become done only
   after Verifier acceptance backed by integrated milestone evidence.
2. Stage 0 is scope, essential design, and local startup. Full test/build setup is
   owned by T-001 alongside the first flow; CI is due at Stage 2 or explicitly release.
3. During implementation run relevant checks. Preserve caches/dependencies. Run broad
   checks at coherent milestones, not every step/handoff. Fresh install is for release
   or justified environment diagnosis. Never silently treat deferred checks as passes.
4. Shared-contract changes require a recorded decision; do not lock every future stub
   before building. Read the actual interface/code you depend on.
5. Never weaken tests, skip failures into green, or loosen configuration silently.
   Tests must fail if claimed behavior breaks. Validate risky behavior as it is built.
6. Declare shortcuts in DEBT. Every ticket names the milestone owning broader checks.
7. Audit records are append-only (LESSONS, DECISIONS, DEBT, LEDGER, evidence). Close
   debt by appending its ID in Closed / accepted, never deleting the original row.
8. Stay in owned scope; describe what was and was not checked. Evidence identifies
   the actual tested implementation, not merely a later evidence/status commit.
9. Default budget: one context window / 2 h. Stop with diagnosis if blocked/exhausted.
10. Human reviews initial intent, integrated demo, consequential risk decisions, and
    release. A passing script is not human sign-off or proof of security.
